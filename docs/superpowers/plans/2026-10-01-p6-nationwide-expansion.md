# P6 全国数据源扩展计划

## 目标与边界

建立 31 个大陆省级规划单元的官方来源发现目录，明确当前证据、覆盖粒度、来源状态和后续审查顺序。香港、澳门、台湾标记 `OUT_OF_SCOPE_PENDING_POLICY_REVIEW`。本计划本身不授权数据采集。

本阶段不进行全国/省级批量下载，不触碰 P5 已验证数据，不调用真实 geocoder，不写坐标、不发布 facilities、不开发地图/附近搜索，不做医院合并、模糊匹配或自动眼科判断。

## 设计决定

1. 数据源只有逐源审批；公开页面或“无条件开放”标记不能单独证明本项目所需的长期存储、应用展示、原始数据转移或再分发权。
2. 本次只建立文档目录及候选审查计划；不新增 schema 或 production code。
3. 现有 `regions` 用带版本的行政区代码/父级关系表达省市区；现有来源快照通过 `source_catalog → import_runs → source_records` 保持来源、run、内容版本追溯。P3 candidates/evidence/duplicate review 关联到来源快照。当前没有独立的 dataset-region coverage 状态表，但本阶段用文档记录；应用需要机器读取 coverage 前再提出独立建模和迁移。
4. P4 的矩形范围 73.5–135.1 / 18.0–53.6 只能做异常 guard，不能等同国界或行政区内判定。未来验证优先基于版本化官方行政区代码及层级；若要多边形校验，应先审查合法来源、许可和版本，不自行绘制政治边界。
5. 现有文件适配器支持 CSV/XLS/XLSX，并仅对显式允许的数据集支持单 XLSX 成员 ZIP-XLSX。它读取本地文件、不发网络请求，可用于手工下载。JSON API 已有通用结构；分页 API/ZIP-CSV 只做将来适配器设计，不提前实现。

## Coverage 状态模型

建议为“地区 × 来源/数据集”维护有限状态：

`not_reviewed → source_found → source_approved → pilot_ready → pilot_imported → qa_passed`

- `source_found` 仅说明找到来源页面。
- `source_approved` 需要权利、访问、字段、保留、归因逐项审核。
- `pilot_ready` 还需要真实文件/API、schema/region校验、抽样方案、回滚和 QA 人员就绪。
- `pilot_imported` 只表示该来源的试点 run 成功，必须记录导入范围和 run ID。
- `qa_passed` 只对具体数据批次和审查样本有效，不代表区域全覆盖。
- UI/API 未来只能从“有效批次及 QA 状态”表达覆盖，不能把来源数、查询入口或某个城市/区县导入映射成“全国覆盖”。
- 失败、来源撤回、文件 stale 应作为附属事件/阻断标志保留审计，不将已导入自动转成覆盖成功。

## 执行阶段

### P6-A（本 PR）：来源盘点与计划

1. 核实 main 包含 PR #10 与 P5 final report/migration 010；确认回归和工作区干净。
2. 盘点大陆 31 个省级代码，列出官方来源锚点、已发现数据集、覆盖粒度、字段/权利缺口，地区未知不推断为无源。
3. 选择三个优先深审候选地区：天津、河北、浙江；均为 `UNKNOWN` 且 `Ready For Pilot = NO`。
4. 对数据模型、坐标范围 guard、coverage 状态与现有 adapter 作只读评估。
5. 将来源和字段未知项记录在 `docs/operations/p6-wave1-readiness.md`。
6. 运行 P1–P5 Unit、Database、Ruff、mypy、diff check；不改数据库与生产代码。

### P6-B（未来独立授权）：逐源准入与受控文件预检

每个来源完成官方主体确认、来源协议/许可审查、访问方式、允许字段、保存/展示/原始传递/保留条件、更新频率、归因、撤回流程和可复现获取后，才可由人工批准。先拿到官方文件并执行 `inspect → dry-run → 人工审阅`。未明确允许自动访问则只走被允许的人工获取路径，禁止自动下载。

### P6-C（未来独立阶段）：受限 pilot、P3 ETL 与 QA

按已批准地区/来源单独导入真实小样本，数据集少于 50 行则使用全部真实行。每个批次留 provenance/import_run_id、source snapshot hash、字段映射、QA 样本及撤回策略。仅完成 QA 后更新该来源批次状态。禁止把样本 QA 外推为全区域覆盖。

## Wave 1 候选地区选择

选择天津、河北、浙江作为优先审查对象，不作排名：

- 天津：官方目录给出 XLS、明确的字段摘要、年度更新频率及近期附件；直辖市作为完整的省级规划单元。法律含义、附件行数/字段/更新、协议和保存展示权仍需审查。
- 河北：官方京津冀协同目录列出河北省医保局“定点医疗机构信息表”和下载入口；仍需定位原始河北发布页面，确认省级覆盖、 schema 与权利。
- 浙江：省级开放平台列出“二级及以上医疗机构基本信息”；显示使用申请，存在受限开放协议，必须先取得并审阅具体批准。

Wave 1 表示审查顺序，不表示批准或可导入。三者当前均未达到 ready 条件。

## 主要风险

- 省级开放目录有登录、受限申请或数据集协议条款，通用平台协议不能替代具体数据集批准。
- “定点医疗机构”覆盖的是医保结算关系，不必然涵盖全部合法医疗机构；“三级医疗机构”也有级别范围限制。
- 公示公告、查询接口的当前性、完整性与可复现性不同于全量快照。
- 省级规划代码和边界会变更；历史行政区代码与来源地域文字需保留原文与代码版本。
- P4 矩形 guard 可能误判边缘/边界点，正式全国扩展前仍需行政区级校验方案和测试样本。
